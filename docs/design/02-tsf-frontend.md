# 共通の窓口（ウィンドウズの TSF）と、日本語版の IME オフ

## 1. 二つの動き方

| 動き方 | 使う所 | キーの扱い |
|---|---|---|
| **素通し＋候補** | 英語版、日本語版の IME オフ | キーはすぐアプリへ。横取りするのは「候補が出ているときの Tab」と「Esc（候補を閉じる）」だけ |
| **組み立て（composition）** | 韓国語、中国語、ベトナム語の Telex、ヒンディー語・アラビア語 | 組み立て中のキーは IME が預かり、下線つきで見せ、確定でアプリへ |

## 2. 素通し＋候補の作り

### 2.1 今の語と前の語の知り方（二段構え）

1. **文書から読む（第一）**: キーの処理が終わった後（ITfTextEditSink の OnEndEdit）に、読み取り専用の編集で
   カーソルの前の最大 64 字を取り、今の語と前の語を切り出す。カーソルの移動、クリック、貼り付け、Backspace に
   強い。メモ帳、Word、Chrome、Edge など TSF に対応したアプリで使える。
2. **キーから追う（第二）**: 文書から読めないアプリ（古いアプリ、TSF の文の取り出しに対応しないもの）では、
   `word_tracker`（芯にある）で打ったキーから追う。フォーカスが替わったら Reset。

どちらで追っているかは内部の状態で持ち、試験の記録に出す。

### 2.2 候補を出すまで

- OnTestKeyDown／OnKeyDown では**芯の計算をしない**（キーを止めない）。決めるのは「Tab を横取りするか」だけで、
  それは前もって計算済みの「今の候補」があるかで決まる。
- 候補の計算は、キーの処理の後に別の糸（スレッド）で行う。新しいキーが来たら古い計算の結果は捨てる。
- 目安: 候補が出るまで 30 ミリ秒以内（芯の補完は 5 µs、直しは 0.6 ms なので余裕がある。測って確かめる）。

### 2.3 Tab で入れる

- 候補が出ているときの Tab だけ横取りし、書き込みの編集で補完の残りを入れる。
- 入れる直前にもう一度カーソルの前を読み、候補を出したときと同じ語のままか確かめる。違えば入れずに Tab を素通しにする
  （遅れて届いた候補で、違う所に文字を入れないため）。

### 2.4 候補の窓

- フォーカスを取らない小さな窓（WS_EX_NOACTIVATE、最前面、タスクバーに出ない）。場所はカーソルの文字の位置
  （ITfContextView::GetTextExt）。取れないときは出さない（あてずっぽうの場所に出さない）。
- 見せ方の案: 補完は薄い字で「meeting　Tab」、直しは「もしかして think」（押すと入れ替え、勝手には替えない）。
- 全画面のアプリ向けに、窓を自分で出さずにアプリに描かせる方式（ITfUIElement）にも対応する（Mozc の TIP と同じ考え方）。

### 2.5 動かない所（必ず素通し）

- **パスワード欄**: 入力の種類（InputScope）が IS_PASSWORD・IS_PIN のとき。読み取り専用のときも。
- **アプリの一覧**: 既定でターミナル（WindowsTerminal.exe、conhost.exe など）、リモートの画面、ゲーム（全画面の
  排他）を入れる。利用者が設定で足し外しできる。
- 一覧の判定は実行ファイルの名前だけで行い、窓の中身は見ない。

## 3. 組み立ての作り

- 組み立てる字の決まりは芯に置く（ハングル `hangul.cc`、Telex `telex.cc`、拼音は Rime）。窓口は
  「キー → 芯 → 下線の文字の更新 → 確定」をするだけにする。
- 韓国語: 1 音節ずつ組み立て、字母でないキーで確定。分かち書きの直しと英語モードの見分けは、確定した後に
  候補として出す（勝手に直さない）。
- ベトナム語 Telex: 声調のキーが前の字を変えるので、1 語を組み立ての範囲にする。空白・句読点で確定。
- 中国語: Rime の候補を窓口の候補の窓に出す（Rime は同じ常駐の中で動かす。Weasel は GPL なので中身は使わず、
  librime（BSD-3）を直接呼ぶ）。

## 4. 表をどこに置くか（大事）

TSF の部品は、文字を打つ全部のアプリの中に読み込まれる。表を各アプリが別々に読み込むと、アプリの数だけ
メモリを使う（英語の表で 57 MB × アプリの数）。

**決め方: 組み立て済みの表を、書き替えない形のファイルの写像（メモリマップ）で読む。**
- OS が同じファイルの頁を全部のアプリで分け合うので、実際のメモリは 1 つ分で済む。
- 読み込みはほぼ 0 秒（読む時に初めて頁が入る）。
- そのため芯の組み立て済みの表は「読み込んで組み立て直す」形でなく「そのまま引ける」形にする（05-core.md）。

重い計算（中国語の模型、日本語の zenz）は今の常駐（mozc_server）と同じく、別の処理の中で 1 つだけ動かす。

## 5. 日本語版の IME オフへのつなぎ方

- Mozc の TIP（win32/tip）の「IME オフのときのキー処理」に、2 章の素通し＋候補を差し込む。
  差し込みは今の作り方と同じく `tools/apply_*.py` の書き替えで行う（上流の Mozc を直接書き替えない）。
- 英語の表は英語パック（本体に同梱の小さい版）からメモリマップで読む。
- IME オンに戻したとき、候補の窓を閉じ、追いかけていた語を Reset する。
- 設定: 「IME オフで英語の補完と直しを使う」（初めは入。止められる）、Tab の代わりのキー。

## 6. 試し方

| 段 | 何を | どこで |
|---|---|---|
| 1 | 決めごと（Tab を取るか、候補の文字列、大文字の合わせ方）| 芯の試験（Linux、GitHub）|
| 2 | TIP が組み立てられるか | GitHub のウィンドウズの流れ |
| 3 | 入れて動くか（メモ帳・Chrome・Word・ターミナル・パスワード欄）| ユーザーのパソコン（入れる前に聞く）|
| 4 | キーの遅れ | 1.164 と同じ記録の仕組みで、素通しのときと比べる |

段 3 の確かめの一覧（毎回同じ物を通す）:
- メモ帳で「the me」→ 候補 meeting、Tab で入る、もう一度 Tab は素通し
- パスワード欄（ブラウザのログイン画面）で候補が一度も出ない
- Windows Terminal で何も起きない
- 候補が出ている間にマウスで別の所をクリック → 候補が消え、Tab は素通し
- 日本語版で IME オン → オフ → オンを繰り返しても候補が残らない

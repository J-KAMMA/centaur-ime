# 言語ごとの設計

数字は 2026-11-05〜06 の GitHub の計測（試験の文は表づくりに使っていない文）。「目標」は次の段で超えたい線。

## 英語

**機能**: 補完（Tab）、打ち間違いの直し（候補を見せるだけ）、スペースなしで打つ書き方（選んで入れる）。

| 項目 | いま | 比べる相手 | 目標 |
|---|---|---|---|
| 直し（一番の候補） | 90.2%、正しい語を替える 0.22% | Hunspell 60.3%、pyspellchecker 78.5%、symspellpy 77.4% | 92%、替える 0.2% 以下 |
| 区切り（まとまり） | 98.3% | wordsegment 92.6% | 98.5% |
| 補完で減る打数 | 26.3% | — | 30%（前の 2 語を見る） |

**次の一手**
1. 表の材料を Tatoeba だけから広げる（ウィキペディア英語版など）。Tatoeba は試験と同じ種類の文なので、今の数字には
   地元の利がある。材料を広げたうえで、Tatoeba 以外の試験の文（ウィキの別の記事など）でも測る。
2. 3 語の並び（前の 2 語）を足すかを測る（表が大きくなるので、メモリマップの形で大きさも見る）。
3. LatinIME との比べを直す（今は比べる仕組みの不具合で答えがおかしい）。Android の直しの考え方（キーの近さの重み）と
   比べ、良い所を取り込む。
4. 名前（Tom、Tanegashima など表に無い語）を直そうとしない決まり: 大文字で始まる語は直しの候補を出さない、を試す。

## 韓国語

**機能**: 2 ボル式の組み立て、分かち書きの直し（候補）、英語モードのまま打った語の見分け（候補）、補完。

| 項目 | いま | 比べる相手 | 目標 |
|---|---|---|---|
| 分かち書き（会話の文、文が合った） | 68.8% | kiwipiepy 77.3% | 78% |
| 分かち書き（ウィキ、文が合った） | 45.7% | kiwipiepy 35.4% | 50% |
| 英語モードの見分け | 見つける 78.9%、英語の語を誤って直す 0.00% | — | 見つける 85%、誤り 0.01% 以下 |

**次の一手**
1. 分かち書き: 今は「字と字の間ごとに数えた割合」。語の単位のビタビ（英語の区切りと同じ芯）と混ぜる。
   材料はウィキペディアの残りの区切りを足す（「모두의 말뭉치」は同意して入手する材料なので使わない）。
2. 英語モードの見分け: 見逃しの 2 割は、Shift を打ち忘れた形（ㄲ が ㄱ になる）と、韓国語の表に無い語。
   - Shift の打ち忘れ: 小文字の並びから「Shift を足した形」も作って表で引く。
   - 表に無い語: 語の表ではなく「音節の並びとしてありそうか」（音節の 2 つの並びの表）で判定する。
3. 見せ方: 空白を打った時に「dkssud → 안녕」と候補を出す。Tab（または決めたキー）で入れ替える。勝手には替えない。
4. 字母の打ち間違いの直し（ㅓ と ㅏ の隣など）は、キーの位置の重みを 2 ボル式の並びで作り直して芯の直しに乗せる。

## 中国語（簡体字）

**土台**: Rime（librime、BSD-3）の luna_pinyin_simp。全拼で文が全部合った 48.2%、字の誤り 12.9%、簡拼 12.0%。
（搜狗や Microsoft 拼音はもっと強いはず。測れていないので、目標は Rime からの上積みで決める。）

**次の一手**
1. 同音字の手がかり: いま よくなった 43、悪くなった 10。悪くなる所を 0 にしてから入れる（日本語と同じ決まり）。
   悪くなる原因は単語の知識の不足 → 中国語ウィキペディア（簡体字に直す）で 2 字の数を増やす。
2. 他・她・它: 前の文の名前（玛丽 → 她、汤姆 → 他）を手がかりにする。文をまたぐ手がかりは日本語にはまだ無いので、
   ここで作り方を試し、日本語にも戻す。
3. 模糊音（z/zh、c/ch、s/sh、n/l、an/ang、en/eng、in/ing）は Rime の綴りの設定で入れる。計測に「模糊音で打つ人」の
   打ち方を足す（例: zh を z と打つ）。
4. 拼音の打ち間違いの直し（zhognguo → zhongguo）は芯の直しで候補を作り、Rime に渡す。
5. 小さな模型（04-models.md）: 文の区切りの誤り（「问题想出了」→「德文提箱除了」）は手がかりでは直らない。ここが本命。

## 繁体字中国語（台湾・香港）

- 計測が動いていない（Rime の bopomofo_tw の出力が空）。空白キーが「第 1 声」として扱われ、候補を選べていない疑い。
  直し方: 確定を空白でなく Enter（または候補の番号キー）で行う。
- 台湾は注音（大千式）、香港は倉頡・速成と粤拼。まず台湾の注音から。字の形の違い（台/臺、裡/裏）は「台湾の標準」に
  そろえて測る。

## ベトナム語

**機能**: Telex（済み、Python と C++ が一致）、VNI（数字で記号）、記号なしで打って文脈から付ける書き方。

| 項目 | いま | 目標 |
|---|---|---|
| 記号なし → 記号つき（会話の文、文が全部合った） | 66.2%（音節 93.7%） | 85% |
| 同（ウィキ） | 99.2%（型どおりの文が多く当てにならない） | 試験の文を作り直す |

**次の一手**
1. ウィキの試験の文から、表づくりの文とほぼ同じものを除いて測り直す。
2. 3 音節の並び、語（複数音節）の単位の表を足す。
3. 記号なしの書き方の見せ方: 空白で記号を付けた形を出し、違えば候補から選ぶ（勝手に替えた後で戻せる）。
4. Telex の声調の置き場: 古い書き方（hòa、thủy）と新しい書き方（hoà、thuỷ）を設定で選べるようにする。Tatoeba の
   語で元に戻る割合を両方で測り、多い方を既定にする。

## ヒンディー語（ほかのインドの言語の手本）

| 項目 | いま | 目標 |
|---|---|---|
| ローマ字 → デーヴァナーガリー（語） | 68.5%（組の表だけ 65.6%、決まった読み方だけ 20.2%） | 90% |
| 同（文が全部合った） | 5.4% | 40% |

**次の一手**
1. 表に無いローマ字が 27%。ここは表では埋まらない → 字の単位の小さな模型（04-models.md）。
2. 候補の見せ方: 一番の候補を下線で見せ、空白で確定。違えば候補（綴りの違い: रही/रहि など）から選ぶ。
3. 同じ作りで、ベンガル語、タミル語、テルグ語、マラーティー語へ（Dakshina に 12 言語ある）。

## アラビア語

| 材料 | 語 | 文 |
|---|---|---|
| モロッコ方言（Darija） | 70.2%（組の重みだけ 73.6%） | 32.9% |
| ほかの材料 | 試験が小さすぎて判断できない | — |

**次の一手**
1. 標準語（フスハー）のウィキの並びを混ぜると下がった → 方言ごとに表を分け、設定で方言を選ぶ（エジプト、湾岸、
   レバント、マグレブ）。
2. 材料: 方言の文の集まりを探す（使ってよい条件のもの）。足りない分は、アラビア文字の方言の文から Arabizi を規則と
   模型で作って増やす（ただし試験には本物の Arabizi だけを使う）。
3. 右から左の表示: 候補の窓と下線を右から左にする。英語が混じる文で向きが崩れないかを確かめる一覧を作る。

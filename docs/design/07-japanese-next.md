# 日本語の次の一手

## 1. 同音語の手がかりを回し続ける仕組み

これまで（#59〜#63）は、候補を数える所は自動、手がかりを選ぶ所は人の目だった。回数を増やせるように、
目で見る量を減らす。

### 1.1 1 回の流れ

```
① 手がかり選びの枠（0.1〜0.8）の文を今の main で変換 → 漢字の取り違えの組を数える（mine-mistakes.yml）
② 取り違えの多い組から、手がかりの候補を数える（mine_homophone_cues.py: 片方とだけ min-df 回以上出る 2〜4 字）
③ 候補の自動のふるい
   - 広すぎる手がかりを落とす: 手がかりが別の語の一部として出る割合が高いもの（例: 管理 → 管理人、摘 → 摘まむ）
     → 手がかり選びの枠で「手がかりを含む文のうち、組のどちらでもない語の中に出ている割合」を数え、高ければ落とす
   - 片方の語でしか出ない手がかりでも、出る数が少なすぎるものは落とす
④ 組ごとに当てて、重み選びの枠（新しく 0.1〜0.15 を取り分ける）で「悪くなった」が 0 の組だけ残す
⑤ 人が最後に一覧を見る（ここは残す。手がかりの意味がおかしい物を落とす）
⑥ 確かめの枠（0.8〜）で比べ、全体試験を流し、悪くなった所が 0 なら main へ
```

### 1.2 変えること

- 組を選ぶのも手がかり選びの枠だけで行う（3 回目までは確かめの枠の誤りから組を選んでいた）。
- ③と④を `tools/` に足し、mine-mistakes.yml の中で回す。
- 1 回で足す組の数の目安: 20〜40 組。足しすぎると悪くなった所の原因を追えない。

### 1.3 広げ方

- 中国語で試す「文をまたぐ手がかり」（前の文の名前で 他/她 を決める）がうまくいけば、日本語にも使う
  （例: 前の文に「病院」があれば「直る/治る」の 治 を選ぶ）。
- 手がかりの表は日本語・中国語で同じ形（同音の組と、組ごとの手がかり）にしておき、道具を共有する。

## 2. 最初の 1 文字がローマ字のままになる件

ユーザーの話: しばらく打たないと、どのアプリでも最初の 1 文字だけローマ字になる。Microsoft IME でも起きる。

### 2.1 手がかり

1.164（キーの記録入り）が組み立て済み。20 秒以上打たなかった後の最初の 6 キーについて、時刻・種類（TestKeyDown か
KeyDown か）・前のキーからの間・IME の開閉・横取りしたか・処理にかかった時間・キーの種類（英字/数字/その他）を記録する
（打った文字そのものは記録しない）。

### 2.2 起きたときの見分け方

| 記録の形 | 考えられる原因 | 直し方の向き |
|---|---|---|
| 最初のキーの行が無い | OS がキーを IME に渡していない（スレッドの入力の受け口が眠っている）| IME だけでは直せない。Microsoft IME でも起きる話と合う |
| 行はあるが、開閉が「閉」| IME の開閉の状態が戻っていない | 状態の同期を見直す |
| 行はあり「開」だが、横取りしていない・時間が長い | 常駐（mozc_server）への問い合わせが間に合っていない | 起きた直後に先に繋いでおく、問い合わせの待ちを見直す |

### 2.3 進め方

1. ユーザーに 1.164 を入れてもらい、起きたときの keytrace.log の「分類」を見る（中身は種類と数だけ）。
2. 表の 3 つのどれかが分かってから直し方を決める。分からないうちは直さない。

# 危ない所と、まだ決めていないこと

## 1. 危ない所

| 危ない所 | 何が起きるか | 先に打つ手 |
|---|---|---|
| アプリとの相性（TSF）| 一部のアプリで候補の窓が変な所に出る、Tab が二重に入る | 窓の場所が取れないときは出さない。Tab は入れる直前に確かめ直す（02 章）。確かめの一覧を毎回通す |
| メモリ | 窓口は全部のアプリに読み込まれる。表を各アプリが持つと重い | 表はメモリマップで分け合う（05 章）|
| キーの遅れ | 素通しのはずが遅れる | キーの処理の中で芯を呼ばない。キーの記録で素通しと比べる |
| パスワード | パスワード欄で候補を出す・覚える | 入力の種類で必ず止める。止めた所の試験を毎回 |
| 学習した中身 | 打った語を覚える機能を足すと、秘密の語が残る | 英語の学習は最初は入れない。入れるなら置き場・消し方・止め方を先に決める |
| 材料の条件 | 配った表・模型に問題のある材料が混ざる | 06 章の決まり。材料ごとに出どころと版を記録 |
| 材料が少ない言語 | アラビア語の Arabizi など | 作った材料で学習しても、試験は本物だけで測る |
| 言語を増やしすぎ | どの言語も中途半端になる | 製品として仕上げるのは 1 つずつ。測るのは並べてよい |
| 名前 | 「Centaur」の名前がほかの製品とぶつかる | 公開の前に、同じ名前の入力の製品が無いか調べる（まだ調べていない）|
| 署名 | 新しい DLL が SmartScreen やウイルス対策に止められる | 今の MSI と同じ署名の仕組みに乗せる |

## 2. まだ決めていないこと（ユーザーに聞くもの）

1. 英語版を単独でも配るか（英語の人向け）、それとも日本語版の IME オフだけにするか。設計は両方できる形にしてある。
2. 言語パックを自動で更新するか（初めは「お知らせだけ」の案）。
3. Microsoft Store に出すか。
4. マック（入力の仕組みが別: InputMethodKit）と Linux（ibus）で、日本語以外の言語をいつ出すか。
5. 次に足す言語の順（今の候補: ヒンディー語 → アラビア語 → ベトナム語 → 繁体字 → タイ語）を、計測を見て変えるか。
6. 中国語の小さな模型の学習を始める時期（Colab を使うので聞く）。

## 3. 調べること

- Rime の bopomofo_tw で注音の計測が空になった理由（空白キーの扱い）。
- LatinIME との比べで答えがおかしい理由（比べる仕組みの側）。
- ベトナム語のウィキで、試験の文と表づくりの文がどれだけ重なっているか。
- 「Centaur IME」と同じ名前の製品があるか。

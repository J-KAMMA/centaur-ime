# 芯（native/centaur_core）の作り

## 1. いまあるもの（work/en-measure の枝）

| 部品 | 中身 | 確かめ |
|---|---|---|
| core | 語の表、2 語の並び、区切り（ビタビ、上位 8）、キーの位置を見た直し（消し字の索引）、補完 | 試作（Python）と 23,663 問で一致 |
| hangul | ハングル ⇄ 2 ボル式のキー | 全 11,172 音節と、でたらめな並び 30,000 個で一致 |
| telex | ベトナム語 Telex の組み立て | でたらめな並び 30,000 個で一致 |

速さ（GitHub の機械、英語の表 78,143 語）: 区切り 0.73 ms、直し 0.63 ms、補完 5 µs。
読み込み: 文字の表 5.7 秒 → 組み立て済みの表 0.6 秒（答えは同じ）。

## 2. 組み立て済みの表を「そのまま引ける」形にする

窓口はアプリごとに読み込まれるので、表はメモリマップで分け合う（02-tsf-frontend.md の 4 章）。
今の組み立て済みの表は、読んだ後に語の表と並びの表を組み立て直している（0.54 秒、メモリも各アプリに要る）。
これを、組み立て直さずに引ける形にする。

```
見出し: 魔法の文字列、版、各区画の位置と長さ
語の区画:     語の文字（UTF-32 を並べたもの）、各語の始まりの位置、出る数
語の引き方:   語のハッシュ → 語の番号（並べた配列、二分探し）
並びの区画:   (前の語の番号, 語の番号, 数) を前の語の番号の順に並べたもの、前の語ごとの始まりと合計
消し字の索引: (ハッシュ, 語の番号) の並べた配列（今と同じ）
補完の索引:   (頭のハッシュ, 始まり) と語の番号の並び（今と同じ）
```
- 全部「並べた配列と二分探し」にする。ポインタを持たないので、ファイルをそのまま写像して使える。
- 語の引き方はハッシュで探し、見つかった語の文字を比べて確かめる（重なりで間違えない）。

**大きさを小さくする**（今 57 MB、目標 20 MB 以下）:
- 消し字の索引が一番大きい（1 組 16 バイト × 約 300 万）。ハッシュを 32 ビットにし（重なりは編集距離で確かめるので
  答えは変わらない）、語の番号を 24 ビットに詰めて 1 組 7 バイトにする → 約 21 MB。
- さらに、消し字を 2 字消しまでではなく「1 字消し＋短い語だけ 2 字消し」にする案。答えが変わるので、変えるなら
  計測で直しの当たりを比べてから。

速くする・小さくする変更は、optimization-adoption の決まり（答えが変わらないことの証明）を通してから入れる。
一致の試験（`tools/en_ime/parity.py`）に「メモリマップの表でも同じ答え」を足す。

## 3. 言語ごとに替える物

| 言語 | 字の単位 | 表 | 直しのキーの位置 |
|---|---|---|---|
| 英語 | 英字 | 語の表 | QWERTY（今の重み）|
| 韓国語 | 音節（直しは字母のキー）| 語（어절）の表、音節の並び | 2 ボル式の並び |
| ベトナム語 | 音節 | 音節の表、記号つきの形の表 | Telex のキー |
| 中国語 | 拼音の音節 | Rime を使う。芯は拼音の打ち間違いの直しだけ | QWERTY |

キーの位置の表は、今は英語の 3 行が芯に直に書いてある。言語ごとに表を渡せる形にする（試作の Python も同じ）。

## 4. 試験の決まり

- 芯を変えたら、試作との一致の試験（区切り・直し・補完・ハングル・Telex）を全部通す。一つでも違えば止まる。
- 試作の方を直すとき（例: 2026-11-06 の「前の語の後に続いた回数」の数え違い）は、芯も同じに直し、計測の数字が
  どう変わったかを記録に残す。
- 境目の問い（空、1 字、とても長い並び、大文字、表に無い語、' を含む語）は毎回混ぜる。

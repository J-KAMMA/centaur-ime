# 測り方の決まり

## 1. 文の分け方（全部の言語で同じ）

文の番号（ウィキは記事の番号）と決まった種（seed）から SHA-256 で 0〜1 の数を作り、その数で分ける。

| 枠 | 使い道 |
|---|---|
| 0 〜 0.1 | 試験（数字を出すだけ。これを見て何かを選ばない）|
| 0.1 〜 0.15 | 重み選び（dev）|
| 0.15 〜 0.8 | 表づくり・手がかり選び・学習 |
| 0.8 〜 1 | 確かめ（手がかりや模型を入れる前の最後の比べ）|

日本語の Tatoeba は今の分け方（0.1 未満が pool、0.1〜0.8 が手がかり選び、0.8 以上が確かめ）を続ける。
**これまでの失敗**: 同音語の 3 回目は、手がかりの組を確かめの枠の誤りから選んでいた。4 回目からは、組を選ぶのも
手がかり選びの枠だけで行う（07-japanese-next.md）。

## 2. 何を数えるか

- **よくなった・悪くなった・変わったがまだ違う** を必ず別に数える（全体の割合だけ見ない）。
- 悪くなった所は全部を一覧にして目で見る（日本語の #62 では、これで 管理→自己、摘→花 を見つけた）。
- 表記の揺れ（分かる/わかる、台/臺）は「ゆるい一致」で同じとみなすが、ゆるい一致の決まり自体は試験の文を見て
  広げない（広げると数字がよく見えるだけになる）。
- 速さは中央と遅い方 1% の両方。

## 3. 一般的な仕組みとの比べ（定期的に）

| 言語 | 相手 | 方法 |
|---|---|---|
| 日本語 | Microsoft IME（手元）、上流の Mozc（GitHub）| Tatoeba の確かめの枠、漢字の取り違えのある文の割合 |
| 英語 | Hunspell、pyspellchecker、symspellpy、wordsegment、LatinIME（直し中）| 同じ打ち間違い |
| 韓国語 | kiwipiepy | 同じ文 |
| 中国語 | Rime（土台そのもの）| 同じ文 |

2026-11-06 の日本語（2,979 文）: 漢字の取り違えがある文 Centaur IME 5.6%、Microsoft IME 10.8%、上流の Mozc 13.6%。

**比べる道具の誤りに気をつける**: Microsoft IME との比べでは、比べる道具のローマ字の表の誤り（yo → ぇ）で
相手が低く出ていた。相手の数字が低すぎるときは、まず道具を疑い、相手の誤りの例を目で見る。

## 4. 関所（main に入れる前）

- 日本語: 全体試験（linux-test.yml）。組を絞った試験だけでは入れない。
- ほかの言語: 言語の計測の流れで、悪くなった数と一致の試験。
- 一致の試験（芯と試作）は毎回。

## 5. 材料の決まり

- 測るだけ（配らない）なら公開の材料は条件を問わず使う。
- 配る表・模型の材料は、著作権法 30 条の 4 に基づき使う。契約で使い方を縛る材料（非営利のみ、研究のみ、規約で学習を
  禁止、同意して入手する物）は使わない。元の文を長く丸ごと配布物に入れない。
- RealPersonaChat（CC BY-SA 扱い。v5 の学習に使ったので試験には使わない）と Meltype（試験の材料だけ、公開の頁に
  名前を出さない）の決まりはそのまま。
- Tatoeba は毎日書き出し直されるので、取った時の SHA-256 を記録に残す。ウィキは版を固定する。
